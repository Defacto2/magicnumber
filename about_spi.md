# BSAVE

BSAVE ("Binary SAVE", paired with BLOAD) is a built-in IBM BASIC / GW-BASIC / QuickBASIC command from the 1980s that  
dumps a raw region of system memory straight to disk.

To save a CGA screen in BASIC, you pointed to CGA video RAM (DEF SEG = &HB800) and ran:

    BSAVE "SCREEN.PIC", 0, 16384

Later, BLOAD "SCREEN.PIC", 0 loaded those bytes straight back into B800:0000 onto the screen.

### The 7-Byte BSAVE Header

Every BSAVE file starts with a 7-byte header followed by the raw memory bytes:

Offset │ Size │ Value (CGA example) │ Meaning
───────────────┼──────────────┼─────────────────────┼─────────────────────────────────────────────────────────────────
0 │ 1 byte │ 0xFD │ BSAVE magic marker
1..2 │ uint16 LE │ 0xB800 (00 B8) │ Memory segment (0xB800 = CGA, 0xB000 = MDA)
3..4 │ uint16 LE │ 0x0000 (00 00) │ Memory offset
5..6 │ uint16 LE │ 0x4000 (00 40) │ Length in bytes (16,384 for CGA graphics, 4,000 for 80×25 text)

That makes a standard BSAVE CGA graphics file 7 + 16,384 = 16,391 bytes (or 16,392 bytes when a trailing 0x1A DOS EOF
byte or 0x00 pad byte was appended, like TITLE.BCC and RAMBO.PIC).

# SPI CGA RLE Format (`SPICGADump`)

Software Pirates, Inc. DOS `.COM` game loaders (such as `FROGGER2.COM`, `MICGOLF.COM`, and `COMMANDO.COM`) embed a CGA graphics splash screen encoded in a boutique Run-Length Encoding (RLE) stream marked by `"SPI"`.

## Binary Layout

The `"SPI"` payload sits inside a DOS `.COM` executable (starting with a `0xE9` or `0xEB` `JMP` and an unencrypted ASCII banner) and runs to the end of the file:

| Offset | Size            | Field       | Description                                  |
| ------ | --------------- | ----------- | -------------------------------------------- |
| `0`    | 3 bytes         | Magic       | ASCII `"SPI"` (`53 50 49`)                   |
| `3`    | 2 bytes         | `pairCount` | `uint16` little-endian number of RLE pairs   |
| `5`    | `2 * pairCount` | Pairs       | Sequence of `[val, repeatMinus1]` byte pairs |

Each `[val, repeatMinus1]` pair writes `val` **`repeatMinus1 + 1` times** sequentially into CGA graphics video RAM (`B800:0000`, 320×200 4-color interleaved layout).

### Example (`FROGGER2.COM`)

- File size: `11,979` bytes (`0x2ECB`)
- `"SPI"` offset: `0x1180`
- `pairCount`: `3,747` (`0x0EA3`), consuming `5 + 2 * 3,747 = 7,499` bytes (`0x1180 + 7,499 = 11,979`, exact EOF)
- Decoded output: `16,376` bytes (`0x3FF8`) of 2-bit-per-pixel CGA raster data

## Compression Background

The compression is a **boutique implementation of textbook 1970s/1980s fixed-pair RLE**:

- `(byte, run-length)` RLE was widely used in early microcomputer graphics, teletext/fax, and standard formats like MacPaint PackBits, PCX, and IFF ILBM.
- Unlike those standard formats, this `"SPI"` format has **no literal/uncompressed run mode** — even a single unrepeated byte is encoded as a 2-byte pair (`[val, 0x00]`). It compresses well on CGA splash screens because they contain long horizontal runs of `0x00`, `0x55`, `0xAA`, and `0xFF`.
- It was hand-rolled for minimal `.COM` loader code size — the x86 decoder in `FROGGER2.COM` (`0x04DC`) is just ~12 instructions writing directly to `ES:DI` (`B800:0000`):

```asm
lodsw              ; AX = pairCount
mov cx, ax
next_pair:
push cx
lodsw              ; AL = val, AH = repeatMinus1
mov cl, ah
sub ch, ch
inc cx             ; CX = repeatMinus1 + 1
rep stosb          ; write AL to B800:DI
pop cx
loop next_pair
```

## Detection (`magicnumber.DumpSPICGA`)

1. File size is `<= 65,536` bytes (`.COM` segment limit) and starts with `0xE9`, `0xEB`, or `"SPI"`.
2. Locate `"SPI"` (`53 50 49`) and read `pairCount` (`uint16` LE) at `idx + 3`.
3. Verify **exact EOF alignment**: `idx + 5 + 2*pairCount == size`.
4. Sum `repeatMinus1 + 1` across all `pairCount` pairs and verify the decoded length is a valid CGA graphics frame (`16000 <= decodedLen <= 16384`).
